# pre-commit 훅이 있을 때

**읽는 조건**: SKILL.md 1번에서 아래 중 하나라도 발견됐을 때만. 없으면 이 문서는 무시한다.

```bash
ls .git/hooks/pre-commit 2>/dev/null
git config core.hooksPath
ls -d .husky lefthook.yml .pre-commit-config.yaml 2>/dev/null
```

> 2026-07-31 기준 BleBridge에는 훅이 없다. 이 문서는 나중에 ktlint·spotless·detekt를 훅으로
> 붙였을 때를 위한 것이다.

## 왜 문제가 되는가

포맷팅 훅은 커밋되는 파일을 **다시 쓴다.** 그 수정은 이미 만들어진 커밋에 들어가지 않고
워킹트리에 남는다. 분할 커밋 루프에서는 두 가지가 깨진다.

1. 방금 만든 커밋이 훅이 고치기 **전** 내용을 담는다 — 커밋과 워킹트리가 불일치한다
2. 남은 수정이 다음 그룹의 `git stash pop`과 같은 파일을 건드려 충돌할 수 있다

## 절차

SKILL.md 5번 커밋 루프의 ③(커밋)과 ④(pop) **사이에** 아래를 끼워 넣는다.

```bash
# ③ 커밋 직후, ④ pop 전
git status --short
```

깨끗하면 그대로 ④로 간다. 깨끗하지 않으면 훅이 파일을 고친 것이다.

**고친 파일이 이 그룹 안에 있을 때** — 방금 커밋에 흡수한다. 아직 pop 전이라 격리가
유지되므로 안전하다.

```bash
git add -- <훅이 고친 파일들>
git commit --amend --no-edit
git status --short          # 이제 깨끗해야 한다
```

이 경우에 한해 `--amend`를 허용한다(SKILL.md의 `--amend` 금지 규칙의 유일한 예외).

**이 그룹 밖의 파일까지 고쳤을 때** — 흡수하지 말고 **중단**한다. 훅이 분할 경계를 넘어
동작하므로 자동 분할이 안전하지 않다. 워킹트리 상태와 훅 이름을 보고에 남긴다.

```
⛔ pre-commit 훅이 이 그룹 밖의 파일을 수정했습니다: <파일 목록>
   분할 경계를 넘어 동작하는 훅이라 자동 분할을 중단했습니다.
   훅을 끄고 다시 실행하거나(`--no-verify`는 이 스킬이 쓰지 않습니다)
   포맷팅을 먼저 적용해 커밋한 뒤 다시 실행하세요.
```

## 사전 회피

훅이 있는 저장소에서는 **커밋 시작 전에 포맷터를 한 번 돌려** 워킹트리를 이미 포맷된
상태로 만들어 두면 위 상황이 거의 생기지 않는다. SKILL.md 2번 검증 단계에서 함께 실행한다.

```bash
./gradlew ktlintFormat    # 또는 spotlessApply
```

이때 포맷터가 바꾼 파일은 해당 그룹에 자연스럽게 포함되므로 별도 처리가 필요 없다.
