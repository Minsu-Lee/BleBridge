ARCHITECTURE

값이 컴포넌트까지 흐르는 순서

각 provider는 상태 수명과 사용 범위에 맞춰 배치하며, 자신의 책임에 해당하는 semantic token만 추가합니다.

01 · MAIN ACTIVITY

AppTheme

앱 전체에 Light/Dark palette, typography, spacing, radius, icon, motion을 제공합니다.

02 · APP / SESSION

ConnectionRoleProvider

역할이 실제로 결정된 범위에서 active/peer 색상과 Material accent를 제공합니다.

03 · CHAT ROUTE

ChatModeProvider

채팅 화면에만 Classic, Hybrid, Terminal의 밀도·글꼴·chrome·노출 정책을 제공합니다.

04 · CHAT UI

Common Component

roleColors와 chatTokens를 읽어 동일한 API로 서로 다른 모습을 그립니다.

HOW TO USE

상태가 살아 있는 범위에 적용

MainActivity에는 foundation만, 역할은 앱·세션 범위에, 채팅 표시 모드는 ChatRoute에 적용합니다.

MainActivity · 앱 전체 Foundation
setContent {
    AppTheme {
        BleBridgeApp()
    }
}
App/Session → ChatRoute · 범위 분리
ConnectionRoleProvider(currentRole) {
    NavHost(/* connected graph */)
}

fun ChatRoute(displayMode: ChatMode) {
    ChatModeProvider(displayMode) {
        val role = AppTheme.roleColors
        val chat = AppTheme.chatTokens

        MessageBubble(
            color = role.active,
            textStyle = chat.messageTextStyle,
            radius = chat.bubbleRadius,
        )
    }
}

ChatContext(role, mode)는 두 provider를 한 번에 준비하는 Preview·UI test·독립 채팅 화면용 편의 API입니다.

BOUNDARY

Feature와 공통 컴포넌트의 책임

✓ 이렇게 사용합니다

  • Foundation, 역할, 채팅 모드를 각 상태 범위에 배치
  • Feature 모델을 ConnectionRole과 ChatMode로 변환
  • 색상과 크기는 semantic token으로 접근
  • 공통 컴포넌트는 roleColors와 chatTokens 소비

× 이렇게 사용하지 않습니다

  • MainActivity에서 역할을 Server로 임의 고정
  • Chat mode를 앱 전체 theme처럼 적용
  • ClassicTheme, HybridTheme처럼 전체 테마 복제
  • Domain 모델이 core:designsystem에 의존
